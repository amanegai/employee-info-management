# 第 3 章 — 案件业务（核心）

本章说明营业最核心的业务流程：**案件マッチング → 选考推进 → 採用確定 → 配属管理**。  
建议配合系统内 **案件マッチング**、**案件詳細** 画面的「ガイド」一起阅读。

---

## 1. 业务概念（必读）

### 1.1 三个关键概念

| 概念 | 含义 |
|------|------|
| **案件** | 客户发来的派遣/SES 需求（技能、人数、期间等） |
| **候補者** | 某案件下正在选考的技术者（可多人并行） |
| **配属** | 客户确定录用后的正式派工记录 |

### 1.2 重要原则

1. **匹配 ≠ 录用**  
   マッチング只是内部参考，不会自动改变社员状态。

2. **可并行选考**  
   同一技术者可同时参加多个客户的面试/审查。

3. **先定先得**  
   某一客户先确定录用（採用確定）后，该员在其他案件中的进行中选考会自动关闭（他案件確定）。

4. **状态由配属驱动**  
   只有「採用確定 + 配属登记」才会让社员变为「稼働中」等状态（经状態提案确认）。

---

## 2. 整体流程图

```
收到客户案件邮件
       │
       ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 案件登録      │ ──► │ 案件マッチング │ ──► │ 候補者追加    │
│ (案件管理)    │     │ (适合度排序)   │     │ (案件詳細)    │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
       ┌──────────────────────────────────────────┘
       ▼
  マッチング済 → 顧客提案済 → 面談設定済み → 選考中
       │
       ▼
  採用確定（输入配属开始日・结束日）
       │
       ▼
  配属作成 → 状態提案で「稼働中」へ
       │
       ▼
  配属结束 / 取消 → 状態提案・フォロー確認
```

## 3. 案件登録

菜单：**案件管理** → **新規案件**

### 3.1 主要输入项

| 项目 | 说明 |
|------|------|
| 取引先 | 从取引先主数据选择，或输入客户名 |
| 案件名 | 便于识别的名称 |
| 必須スキル / 尚可スキル | 影响マッチング精度 |
| 募集人数 | 需要几人；可设为「多名」 |
| 想定開始日 / 終了日 | 案件整体期间（≠ 个人配属期间） |
| 案件テキスト | 可粘贴客户原始邮件内容 |

### 3.2 案件状态

| 状态（画面显示） | 含义 |
|------------------|------|
| 募集中 | 正在招募 |
| 一部確定 | 部分人数已确定 |
| 満員 | 人数已满 |
| 保留 | 暂时搁置 |
| 終了 | 案件结束 |
| キャンセル | 已取消 |

**只有「募集中」「一部確定」的案件可以进行マッチング。**

---

## 4. 案件マッチング

菜单：**案件マッチング**

### 4.1 方式一：从已有案件匹配

1. 左侧案件一覧中选择目标案件（募集中/一部確定）
2. 点击 **マッチング** 按钮
3. 系统根据案件技能要求，按适合度从高到低列出社员
4. 查看每人得分与匹配理由

### 4.2 方式二：粘贴文本临时匹配

1. 将客户邮件内容粘贴到文本框
2. 点击 **マッチング実行**
3. 查看匹配结果
4. 可选 **案件として登録** 将此次内容保存为新案件

### 4.3 添加候補者

在匹配结果中：

1. 勾选要提案的社员
2. 点击 **候補に追加**（或类似按钮）
3. 候補者以「マッチング済」阶段出现在案件詳細

---

## 5. 案件詳細与选考推进

菜单：**案件管理** → 点击案件行 → **案件詳細**

### 5.1 候補者进度阶段

画面上每位候補者有一条进度条，阶段顺序为：

| 顺序 | 阶段名 | 营业动作 |
|------|--------|----------|
| 1 | マッチング済 | 系统匹配后自动 |
| 2 | 顧客提案済 | 已向客户发送简历/提案书 |
| 3 | 面談設定済み | 面试日期已确定 |
| 4 | 選考中 | 面试进行中 / 等待结果 |
| 5 | 採用確定 | 客户确定录用 |

### 5.2 推进阶段

在候補者卡片上点击对应按钮（如 **顧客提案済にする**、**選考中にする**），按实际业务进度逐步推进。

### 5.3 不採用 / 提案撤回

| 操作 | 使用场景 |
|------|----------|
| **不採用** | 客户明确拒绝该人选 |
| **提案撤回** | 我方主动撤回提案（如人选不再合适） |

操作前系统会要求确认。

### 5.4 採用確定（最重要）

客户确定录用时：

1. 点击该候補者的 **採用確定** 按钮
2. 在弹出窗口中输入：
   - **配属開始日**（必填）
   - **配属終了日**（如有）
   - 案件での役割（PM、SE 等，可选）
3. 点击 **採用確定** 提交

**系统自动处理：**

- 创建配属记录（PLANNED → 按开始日变为稼働）
- 该员在其他案件中的进行中选考 → 自动变为「他案件確定」
- 生成状態変更提案（待您在「状態提案」画面确认）

---

## 6. 配属管理

### 6.1 查看配属

- **案件詳細** 的配属区块
- **社員詳細** → 案件・配属 Tab → 配属履歴

### 6.2 修改配属

如需调整结束日、角色等：在配属记录上点击 **編集**。

### 6.3 配属取消

客户中途取消派工时：

1. 在配属记录点击 **取消**
2. 确认取消
3. 系统自动创建 **配属取消フォロー** 任务
4. 侧栏「配属取消フォロー」出现徽章 → 前往处理

> **注意**：配属取消后，之前在 LOST 状态的其他案件选考**不会自动恢复**，需重新マッチング或手动追加候補。

---

## 7. 状態提案（每日确认）

菜单：**状態提案**

系统根据配属的开始日/结束日，每日自动生成社员状态变更建议，例如：

| 建议 | 典型原因 |
|------|----------|
| 待機中 → 稼働中 | 配属开始日已到 |
| 稼働中 → 案件終了間近 | 配属结束日在 N 天内 |
| 案件終了間近 → 待機中 | 配属已结束且无新配属 |

### 操作

| 按钮 | 含义 |
|------|------|
| **適用** | 同意建议，更新社员稼働状態 |
| **無視** | 暂不处理（如实际情况有出入） |

**建议每个营业日上午先处理未完成的状態提案。**

---

## 8. 配属取消フォロー

菜单：**配属取消フォロー**

| 步骤 | 说明 |
|------|------|
| 1 | 查看取消的配属、涉及社员与案件 |
| 2 | 确认是否需要重新提案、联系客户 |
| 3 | 处理完毕后点击 **完了** |
| 4 | 无需跟进则点击 **却下** |

侧栏菜单上的**红色数字**表示未完成任务数。

---

## 9. 完整案例 walkthrough

**背景**：客户 A 公司发来 Java 案件，需要 1 人，下月 1 日开始。

| 步骤 | 操作 | 画面 |
|------|------|------|
| 1 | 粘贴邮件、执行匹配 | 案件マッチング |
| 2 | 登记案件，追加 top3 为候補 | 案件マッチング → 案件詳細 |
| 3 | 向客户发送张三简历，推进阶段 | 案件詳細：张三 → 顧客提案済 |
| 4 | 客户安排面试 | 面談設定済み → 選考中 |
| 5 | 客户确定录用张三 | 採用確定，开始日=下月1日 |
| 6 | 确认李四王五自动 LOST | 案件詳細候補一覧 |
| 7 | 次日确认状態提案 | 状態提案：张三 → 稼働中，適用 |

---

## 10. 常见误操作提醒

| 误操作 | 后果 | 正确做法 |
|--------|------|----------|
| 仅マッチング就认为已派工 | 社员状态不变 | 必须完成採用確定 |
| 採用確定但不填开始日 | 无法创建有效配属 | 必填配属開始日 |
| 忽略状態提案 | 一覧显示状态与实际不符 | 每日確認并適用 |
| 配属取消后忘记フォロー | 遗漏再提案 | 处理フォロー任务 |
