# 第 3 章 — 案件业务（核心业务）

本章说明营业核心流程：**案件マッチング → 选考推进 → 採用確定 → 配属管理**。  
请与系统内 **案件マッチング**、**案件詳細** 的「ガイド」对照阅读。

---

## 1. 业务思路（必读）

### 1.1 三个重要概念

| 概念 | 含义 |
|------|------|
| **案件** | 客户的派遣／SES 需求（技能、人数、期间等） |
| **候補者** | 某案件下选考中的技术者（可多人并行） |
| **配属** | 客户确认录用后正式的派遣记录 |

### 1.2 重要原则

1. **マッチング ≠ 採用**  
   匹配仅供社内参考，不会自动改变社员状态。

2. **选考可并行**  
   同一技术者可同时参加多家客户的面谈・审查。

3. **先到优先**  
   某客户採用確定后，该社员其他案件进行中的选考会自动结束（他案件確定）。

4. **状态由配属决定**  
   「採用確定 ＋ 配属登记」之后，经状態提案更新为「稼働中」等。

---

## 2. 整体流程

```
收到客户案件邮件
       │
       ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 案件登记      │ ──► │ 案件マッチング │ ──► │ 候補者追加    │
│ (案件管理)    │     │ (适合度排序)   │     │ (案件詳細)    │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
       ┌──────────────────────────────────────────┘
       ▼
  マッチング済 → 顧客提案済 → 面談設定済み → 選考中
       │
       ▼
  採用確定（输入配属開始日・終了日）
       │
       ▼
  创建配属 → 状態提案改为「稼働中」
       │
       ▼
  配属終了／取消 → 确认状態提案与フォロー
```

## 3. 案件登记

菜单：**案件管理** → **新規案件**

### 3.1 主要输入项

| 项目（画面示例） | 说明 |
|------------------|------|
| 取引先 | 从取引先主数据选择 |
| 案件名 | 便于识别的名称 |
| ステータス | 募集中 等 |
| 必要人数 | 所需人数。可选「複数名」（无上限） |
| 勤務地／役割 | 现场信息、想定角色 |
| 面談回数 | 客户侧面谈次数等 |
| 開始予定日／終了予定日 | 案件整体期间（与个人配属期间不同） |
| 必要スキル／任意スキル | 影响匹配精度 |
| 請求単価 | 案件单价信息 |
| 案件内容 | 可粘贴客户邮件原文 |
| 備考 | 自由备注 |

### 3.2 案件ステータス

| ステータス（画面显示） | 含义 |
|------------------------|------|
| 募集中 | 募集中 |
| 一部確定 | 部分人数已确定 |
| 満員 | 已满员 |
| 保留 | 暂时保留 |
| 終了 | 案件结束 |
| キャンセル | 已取消 |

**仅「募集中」「一部確定」的案件可以匹配。**

案件一覧サマリー：募集中／一部確定／満員／全案件。

---

## 4. 案件マッチング

菜单：**案件マッチング**

### 4.1 方法 1：从已登记案件匹配

1. 在左侧 **募集中案件** 列表选择目标案件（募集中／一部確定）
2. 点击 **マッチング**
3. 按技能要求显示适合度从高到低的社员
4. 确认各人得分与匹配理由

### 4.2 方法 2：粘贴文本临时匹配

1. 在「案件内容を貼り付けて検索」等文本框粘贴客户邮件
2. 点击 **マッチング実行**
3. 确认结果
4. 必要时登记为案件并追加候補

### 4.3 追加候補者

1. 勾选要提案的社员
2. 点击 **候補に追加**
3. 候補者以「マッチング済」阶段出现在案件詳細

---

## 5. 案件詳細与选考推进

菜单：**案件管理** → 点击案件行 → **案件詳細**

画面上方 KPI 示例：ステータス、請求単価、確定人数／必要人数。

### 5.1 候補者进度阶段

各候補有进度条，顺序如下。

| 顺序 | 阶段名 | 下一步按钮（例） |
|------|--------|------------------|
| 1 | マッチング済 | **顧客提案済へ** |
| 2 | 顧客提案済 | **面談設定済みへ** |
| 3 | 面談設定済み | **選考中へ** |
| 4 | 選考中／内定待ち | **採用確定** |
| 5 | 採用確定 | — |

短标签示例：マッチング → 顧客提案 → 面談設定 → 選考中 → 採用確定。

### 5.2 如何推进阶段

点击候補カード上的按钮，按实际进度推进。

### 5.3 不採用／撤回

| 操作（画面显示） | 使用场景 |
|------------------|----------|
| **不採用** | 客户明确不录用 |
| **撤回** | 社内原因撤回提案 |

执行前有确认对话框。不採用理由示例：顧客不採用、社内撤回、他案件で採用確定、社員都合、案件終了。

### 5.4 採用確定（最重要）

客户确认录用时：

1. 点击该候補的 **採用確定**
2. モーダル标题示例：**採用確定 — {氏名}**
3. 输入：
   - **配属開始日**（必填）
   - **配属終了日**（可选）
   - 案件中的役割（PM、PL、SE、PG 等，可选）
4. 点击 **採用確定** 提交

**系统自动处理：**

- 创建配属记录（開始予定 → 随開始日变为稼働中）
- 其他案件进行中选考 → 自动变为「他案件確定」
- 生成状態変更提案（在 **状態提案** 画面确认）

配属ステータス示例：開始予定／稼働中／完了／取消。  
役割标签示例：PM＝プロジェクトマネージャー、PL＝プロジェクトリーダー、SE＝システムエンジニア、PG＝プログラマ。

## 6. 配属管理

### 6.1 确认配属

- **案件詳細** 的配属区块
- **社員詳細** → 案件・配属 Tab → 配属履歴

### 6.2 变更配属

调整終了日或役割：点击 **編集**。

### 6.3 配属取消

客户中途取消派遣时：

1. 点击配属记录的 **取消**
2. 确认取消
3. 系统自动创建 **配属取消フォロー** 任务
4. 侧栏「配属取消フォロー」出现徽章 → 去处理

> **注意**：配属取消后，此前变为「他案件確定」的其他案件选考**不会自动恢复**。请重新匹配或手动追加候補。

---

## 7. 状態提案（建议每天确认）

菜单：**状態提案**  
画面标题：**状態変更提案**

根据配属開始日／終了日提出社员状态变更，例如：

| 提案 | 典型原因 |
|------|----------|
| 待機中 → 稼働中 | 到达配属開始日 |
| 稼働中 → 案件終了間近 | 配属終了日临近 |
| 案件終了間近 → 待機中 | 配属已结束且无新配属 |

### 操作

| 按钮 | 含义 |
|------|------|
| **適用** | 批准提案并更新稼働状態 |
| **無視** | 暂不处理（与实际不符时等） |

列表会显示 **未処理提案**。**建议每天早晨先处理未处理的状態提案。**

---

## 8. 配属取消フォロー

菜单：**配属取消フォロー**

| 步骤 | 说明 |
|------|------|
| 1 | 在 **未完了タスク** 中确认被取消的配属及相关社员・案件 |
| 2 | 判断是否需要再提案或联系客户 |
| 3 | 处理完成后点击 **完了** |
| 4 | 有「期限超過」显示时优先处理 |

> 「無視」仅管理员可用。营业用 **完了** 关闭任务。

侧栏**红色数字**为未完成任务数。

---

## 9. 示例：完整流程

**情况**：A 社 Java 案件，1 名，下月 1 日开始。

| 步骤 | 操作 | 画面 |
|------|------|------|
| 1 | 粘贴邮件并执行匹配 | 案件マッチング |
| 2 | 登记案件，将前 3 名加入候補 | 案件マッチング → 案件詳細 |
| 3 | 向客户发送田中さんの履歴書并推进阶段 | 案件詳細：田中 → 顧客提案済へ |
| 4 | 客户设定面谈 | 面談設定済みへ → 選考中へ |
| 5 | 田中さん採用確定 | 採用確定，開始日＝下月 1 日 |
| 6 | 确认佐藤・鈴木自动变为「他案件確定」 | 案件詳細候補一覧 |
| 7 | 次日确认状態提案 | 状態提案：田中 → 稼働中，適用 |

## 9b. BP求援与临时候补

社内人员不够时，可向其他营业请求协助寻找 BP 候补。

### 发起求援（仅案件创建人・自社担当・管理者）

1. 在 **案件詳細** 发起 BP求援（填写需要人数・留言）
2. 其他营业会在头部通知和侧栏「BP求援」中看到

### 临时候补流程

```
提交简历 → 担当确认 → 提交客户 → 面谈调整 → 面谈结果等待 → 采用确定
                                    ↘ 不采用 / 辞退
待确认 ↘ 却下 / 取下
```

- **采用确定**：登记为 BP 社员，简历挂到该社员，并创建配属。详细信息请到社员画面补全。
- **不合格・取下**：为保护个人信息，简历文件会被删除（画面显示「削除済み」）。

可通过菜单 **BP求援** 查看求援中的案件一览。

## 10. 常见误操作

| 误操作 | 结果 | 正确做法 |
|--------|------|----------|
| 以为匹配完就算已派遣 | 社员状态不变 | 必须做到採用確定 |
| 採用確定时開始日留空 | 无法建立有效配属 | 配属開始日必填 |
| 一直無視状態提案 | 一覧状态与实际不符 | 每天确认并適用 |
| 配属取消后忘记フォロー | 漏再提案 | 处理フォロー任务 |
| 満员后只改人数、状态仍显示満员 | 旧问题。现行保存时会重算 | 保存人数后会回到一部確定／募集中 |
| 试图在别人的案件上发起 BP求援 | 权限错误 | 仅创建人・担当・管理者可操作 |
