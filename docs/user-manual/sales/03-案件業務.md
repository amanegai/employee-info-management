# 第 3 章 — 案件業務（中心業務）

本章では営業の中核となる業務フロー **案件マッチング → 選考推進 → 採用確定 → 配属管理** を説明します。  
システム内の **案件マッチング**、**案件詳細** 画面の「ガイド」とあわせてお読みください。

---

## 1. 業務の考え方（必読）

### 1.1 3 つの重要概念

| 概念 | 意味 |
|------|------|
| **案件** | 顧客からの派遣／SES 要件（スキル、人数、期間など） |
| **候補者** | ある案件で選考中の技術者（複数人を並行可能） |
| **配属** | 顧客が採用を確定した後の正式な派遣記録 |

### 1.2 重要な原則

1. **マッチング ≠ 採用**  
   マッチングは社内参考用であり、社員の状態は自動では変わりません。

2. **選考の並行**  
   同一技術者が複数顧客の面談・審査に同時参加できます。

3. **先着優先**  
   ある顧客で採用確定すると、その社員の他案件の進行中選考は自動的に終了します（他案件確定）。

4. **状態は配属で決まる**  
   「採用確定 ＋ 配属登録」のあと、状態提案を経て「稼働中」などに更新されます。

---

## 2. 全体フロー

```
顧客から案件メール受信
       │
       ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 案件登録      │ ──► │ 案件マッチング │ ──► │ 候補者追加    │
│ (案件管理)    │     │ (適合度順)     │     │ (案件詳細)    │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
       ┌──────────────────────────────────────────┘
       ▼
  マッチング済 → 顧客提案済 → 面談設定済み → 選考中
       │
       ▼
  採用確定（配属開始日・終了日を入力）
       │
       ▼
  配属作成 → 状態提案で「稼働中」へ
       │
       ▼
  配属終了／取消 → 状態提案・フォロー確認
```

## 3. 案件登録

メニュー：**案件管理** → **新規案件**

### 3.1 主な入力項目

| 項目（画面表示例） | 説明 |
|--------------------|------|
| 取引先 | 取引先マスタから選択 |
| 案件名 | 識別しやすい名称 |
| ステータス | 募集中 など |
| 必要人数 | 必要人数。「複数名」（無制限）設定も可能 |
| 勤務地／役割 | 現場情報、想定役割 |
| 面談回数 | 顧客側の面談回数など |
| 開始予定日／終了予定日 | 案件全体の期間（個人の配属期間とは別） |
| 必要スキル／任意スキル | マッチング精度に影響 |
| 請求単価 | 案件の単価情報 |
| 案件内容 | 顧客メール原文の貼り付け可 |
| 備考 | 自由記述 |

### 3.2 案件ステータス

| ステータス（画面表示） | 意味 |
|------------------------|------|
| 募集中 | 募集中 |
| 一部確定 | 一部の人数が確定済み |
| 満員 | 定員に達した |
| 保留 | 一時保留 |
| 終了 | 案件終了 |
| キャンセル | キャンセル |

**マッチングできるのは「募集中」「一部確定」の案件のみです。**

案件一覧のサマリー：募集中／一部確定／満員／全案件。

---

## 4. 案件マッチング

メニュー：**案件マッチング**

### 4.1 方法 1：登録済み案件からマッチング

1. 左の **募集中案件** 一覧で対象案件を選択（募集中／一部確定）
2. **マッチング**ボタンをクリック
3. 案件のスキル要件に基づき、適合度の高い順に社員が表示されます
4. 各人のスコアとマッチング理由を確認

### 4.2 方法 2：テキストを貼り付けて仮マッチング

1. 「案件内容を貼り付けて検索」などのテキスト欄に顧客メールを貼り付け
2. **マッチング実行**をクリック
3. 結果を確認
4. 必要なら案件として登録し、候補に追加

### 4.3 候補者の追加

マッチング結果で：

1. 提案する社員にチェック
2. **候補に追加**をクリック
3. 候補者は「マッチング済」ステージで案件詳細に表示されます

---

## 5. 案件詳細と選考の推進

メニュー：**案件管理** → 案件の行をクリック → **案件詳細**

画面上部の KPI 例：ステータス、請求単価、確定人数／必要人数。

### 5.1 候補者の進捗ステージ

各候補者に進捗バーが表示され、ステージは次の順序です。

| 順序 | ステージ名 | 次の操作ボタン（例） |
|------|------------|----------------------|
| 1 | マッチング済 | **顧客提案済へ** |
| 2 | 顧客提案済 | **面談設定済みへ** |
| 3 | 面談設定済み | **選考中へ** |
| 4 | 選考中／内定待ち | **採用確定** |
| 5 | 採用確定 | — |

進捗の短いラベル例：マッチング → 顧客提案 → 面談設定 → 選考中 → 採用確定。

### 5.2 ステージの進め方

候補者カード上のボタンをクリックし、実際の進捗に合わせて進めます。

### 5.3 不採用／撤回

| 操作（画面表示） | 利用シーン |
|------------------|------------|
| **不採用** | 顧客が明確に不採用とした場合 |
| **撤回** | 社内都合で提案を取り下げる場合 |

実行前に確認ダイアログが表示されます。不採用理由の例：顧客不採用、社内撤回、他案件で採用確定、社員都合、案件終了。

### 5.4 採用確定（最重要）

顧客が採用を確定したとき：

1. 該当候補者の **採用確定**ボタンをクリック
2. モーダル見出し例：**採用確定 — {氏名}**
3. 次を入力：
   - **配属開始日**（必須）
   - **配属終了日**（あれば）
   - 案件での役割（PM、PL、SE、PG など、任意）
4. **採用確定**をクリックして送信

**システムが自動処理すること：**

- 配属レコードの作成（開始予定 → 開始日に応じて稼働中へ）
- 他案件の進行中選考 → 自動的に「他案件確定」
- 状態変更提案の生成（**状態提案**画面で確認）

配属ステータス例：開始予定／稼働中／完了／取消。  
役割ラベル例：PM＝プロジェクトマネージャー、PL＝プロジェクトリーダー、SE＝システムエンジニア、PG＝プログラマ。

## 6. 配属管理

### 6.1 配属の確認

- **案件詳細**の配属ブロック
- **社員詳細** → 案件・配属タブ → 配属履歴

### 6.2 配属の変更

終了日や役割の調整：**編集**をクリック。

### 6.3 配属取消

顧客都合で派遣が途中取消になった場合：

1. 配属記録の **取消**をクリック
2. 取消を確認
3. システムが **配属取消フォロー** タスクを自動作成
4. サイドバー「配属取消フォロー」にバッジ → 処理へ

> **注意**：配属取消後、以前「他案件確定」になった他案件の選考は**自動復帰しません**。再度マッチングするか、手動で候補を追加してください。

---

## 7. 状態提案（毎日確認）

メニュー：**状態提案**  
画面見出し：**状態変更提案**

配属の開始日／終了日に基づき、社員の状態変更が提案されます。例：

| 提案 | 典型的な理由 |
|------|--------------|
| 待機中 → 稼働中 | 配属開始日に到達 |
| 稼働中 → 案件終了間近 | 配属終了日が近い |
| 案件終了間近 → 待機中 | 配属終了、新規配属なし |

### 操作

| ボタン | 意味 |
|--------|------|
| **適用** | 提案を承認し、稼働状態を更新 |
| **無視** | 保留（実態と異なる場合など） |

一覧に **未処理提案** が表示されます。**毎朝、未処理の状態提案を先に確認することを推奨します。**

---

## 8. 配属取消フォロー

メニュー：**配属取消フォロー**

| 手順 | 説明 |
|------|------|
| 1 | **未完了タスク**で取消された配属、関係する社員・案件を確認 |
| 2 | 再提案や顧客連絡が必要か判断 |
| 3 | 対応完了後 **完了**をクリック |
| 4 | 期限超過の表示がある場合は優先対応 |

> 「無視」操作は管理者のみです。営業は **完了** でクローズします。

サイドバーの**赤い数字**は未完了タスク数です。

## 9. 事例：一通りの流れ

**状況**：A 社から Java 案件。1 名、来月 1 日開始。

| 手順 | 操作 | 画面 |
|------|------|------|
| 1 | メールを貼り付け、マッチング実行 | 案件マッチング |
| 2 | 案件登録、上位 3 名を候補追加 | 案件マッチング → 案件詳細 |
| 3 | 田中さんの履歴書を顧客へ送付、ステージ進行 | 案件詳細：田中 → 顧客提案済へ |
| 4 | 顧客が面談を設定 | 面談設定済みへ → 選考中へ |
| 5 | 田中さんの採用確定 | 採用確定、開始日＝来月 1 日 |
| 6 | 佐藤・鈴木が自動で「他案件確定」になったことを確認 | 案件詳細の候補一覧 |
| 7 | 翌日、状態提案を確認 | 状態提案：田中 → 稼働中、適用 |

## 9b. BP求援と臨時候補

社内要員が足りないとき、他営業に BP 候補の協力を依頼できます。

### 求援の開始（案件の作成者・自社担当・管理者のみ）

1. **案件詳細**で BP求援を開始（必要人数・伝言を入力）
2. 他営業のヘッダー通知・サイドバー「BP求援」に反映されます

### 臨時候補の流れ

```
履歴書提出 → 担当確認 → 顧客提出 → 面談調整 → 面談結果待ち → 採用確定
                                         ↘ 不採用 / 辞退
提出待ち ↘ 却下 / 取下げ
```

- **採用確定**：BP 社員として登録し、履歴書を社員へ紐付け、配属を作成します。詳細情報は社員画面で補完してください。
- **不合格・取下げ**：履歴書ファイルは個人情報保護のため削除されます（画面上は「削除済み」表示）。

メニュー **BP求援** から求援中案件の一覧を確認できます。

## 10. よくある誤操作

| 誤操作 | 結果 | 正しい対応 |
|--------|------|------------|
| マッチングだけで派遣済みと思う | 社員状態は変わらない | 必ず採用確定まで実施 |
| 採用確定で開始日を空欄 | 有効な配属が作れない | 配属開始日は必須 |
| 状態提案を無視し続ける | 一覧の状態が実態とずれる | 毎日確認して適用 |
| 配属取消後にフォローを忘れる | 再提案の漏れ | フォロータスクを処理 |
| 満員後に人数だけ増やして状態が満員のまま | 以前の不具合。現行は保存時に再計算 | 人数を保存すれば一部確定／募集中へ戻る |
| 他人の案件で BP求援を開始しようとする | 権限エラー | 作成者・担当・管理者のみ |
