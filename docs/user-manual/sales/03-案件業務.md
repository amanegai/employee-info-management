# 第 3 章 — 案件業務（中心業務）

本章では営業の中核となる業務フロー **案件マッチング → 選考推進 → 採用確定 → 配属管理** を説明します。  
システム内の **案件マッチング**、**案件詳細** 画面の「ガイド」とあわせてお読みください。

---

## 1. 業務の考え方（必読）

### 1.1 3 つの重要概念

| 概念 | 意味 |
|------|------|
| **案件** | 顧客からの派遣／SES 要件（スキル、人数、期間など） |
| **候補者** | ある案件で選考中の技術者（複数人を並行可能） |
| **配属** | 顧客が採用を確定した後の正式な派遣記録 |

### 1.2 重要な原則

1. **マッチング ≠ 採用**  
   マッチングは社内参考用であり、社員の状態は自動では変わりません。

2. **選考の並行**  
   同一技術者が複数顧客の面談・審査に同時参加できます。

3. **先着優先**  
   ある顧客で採用確定すると、その社員の他案件の進行中选考は自動的に終了します（他案件確定）。

4. **状態は配属で決まる**  
   「採用確定 ＋ 配属登録」のあと、状態提案を経て「稼働中」などに更新されます。

---

## 2. 全体フロー

```
顧客から案件メール受信
       │
       ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 案件登録      │ ──► │ 案件マッチング │ ──► │ 候補者追加    │
│ (案件管理)    │     │ (適合度順)     │     │ (案件詳細)    │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
       ┌──────────────────────────────────────────┘
       ▼
  マッチング済 → 顧客提案済 → 面談設定済み → 選考中
       │
       ▼
  採用確定（配属開始日・終了日を入力）
       │
       ▼
  配属作成 → 状態提案で「稼働中」へ
       │
       ▼
  配属終了／取消 → 状態提案・フォロー確認
```

---

## 3. 案件登録

メニュー：**案件管理** → **新規案件**

### 3.1 主な入力項目

| 項目 | 説明 |
|------|------|
| 取引先 | 取引先マスタから選択、または顧客名を入力 |
| 案件名 | 識別しやすい名称 |
| 必須スキル／尚可スキル | マッチング精度に影響 |
| 募集人数 | 必要人数。「多名」設定も可能 |
| 想定開始日／終了日 | 案件全体の期間（個人の配属期間とは別） |
| 案件テキスト | 顧客メール原文の貼り付け可 |

### 3.2 案件ステータス

| ステータス（画面表示） | 意味 |
|------------------------|------|
| 募集中 | 募集中 |
| 一部確定 | 一部の人数が確定済み |
| 満員 | 定員に達した |
| 保留 | 一時保留 |
| 終了 | 案件終了 |
| キャンセル | キャンセル |

**マッチングできるのは「募集中」「一部確定」の案件のみです。**

---

## 4. 案件マッチング

メニュー：**案件マッチング**

### 4.1 方法 1：登録済み案件からマッチング

1. 左の案件一覧で対象案件を選択（募集中／一部確定）
2. **マッチング**ボタンをクリック
3. 案件のスキル要件に基づき、適合度の高い順に社員が表示されます
4. 各人のスコアとマッチング理由を確認

### 4.2 方法 2：テキストを貼り付けて仮マッチング

1. 顧客メールの内容をテキスト欄に貼り付け
2. **マッチング実行**をクリック
3. 結果を確認
4. 必要なら **案件として登録** で新規案件として保存

### 4.3 候補者の追加

マッチング結果で：

1. 提案する社員にチェック
2. **候補に追加**（または同様のボタン）をクリック
3. 候補者は「マッチング済」ステージで案件詳細に表示されます

---

## 5. 案件詳細と選考の推進

メニュー：**案件管理** → 案件の行をクリック → **案件詳細**

### 5.1 候補者の進捗ステージ

各候補者に進捗バーが表示され、ステージは次の順序です。

| 順序 | ステージ名 | 営業の作業 |
|------|------------|------------|
| 1 | マッチング済 | マッチング後に自動 |
| 2 | 顧客提案済 | 履歴書／提案書を顧客へ送付済み |
| 3 | 面談設定済み | 面談日が確定 |
| 4 | 選考中 | 面談実施中／結果待ち |
| 5 | 採用確定 | 顧客が採用を確定 |

### 5.2 ステージの進める

候補者カード上のボタン（**顧客提案済にする**、**選考中にする** など）をクリックし、実際の進捗に合わせて進めます。

### 5.3 不採用／提案撤回

| 操作 | 利用シーン |
|------|------------|
| **不採用** | 顧客が明確に不採用とした場合 |
| **提案撤回** | 社内都合で提案を取り下げる場合 |

実行前に確認ダイアログが表示されます。

### 5.4 採用確定（最重要）

顧客が採用を確定したとき：

1. 該当候補者の **採用確定**ボタンをクリック
2. ダイアログで次を入力：
   - **配属開始日**（必須）
   - **配属終了日**（あれば）
   - 案件での役割（PM、SE など、任意）
3. **採用確定**をクリックして送信

**システムが自動処理すること：**

- 配属レコードの作成（PLANNED → 開始日に応じて稼働へ）
- 他案件の進行中选考 → 自動的に「他案件確定」
- 状態変更提案の生成（**状態提案**画面で確認）

---

## 6. 配属管理

### 6.1 配属の確認

- **案件詳細**の配属ブロック
- **社員詳細** → 案件・配属タブ → 配属履歴

### 6.2 配属の変更

終了日や役割の調整：**編集**をクリック。

### 6.3 配属取消

顧客都合で派遣が途中取消になった場合：

1. 配属記録の **取消**をクリック
2. 取消を確認
3. システムが **配属取消フォロー** タスクを自動作成
4. サイドバー「配属取消フォロー」にバッジ → 処理へ

> **注意**：配属取消後、以前 LOST になった他案件の選考は**自動復帰しません**。再度マッチングするか、手動で候補を追加してください。

---

## 7. 状態提案（毎日確認）

メニュー：**状態提案**

配属の開始日／終了日に基づき、毎日社員の状態変更が提案されます。例：

| 提案 | 典型的な理由 |
|------|--------------|
| 待機中 → 稼働中 | 配属開始日に到達 |
| 稼働中 → 案件終了間近 | 配属終了日が N 日以内 |
| 案件終了間近 → 待機中 | 配属終了、新規配属なし |

### 操作

| ボタン | 意味 |
|--------|------|
| **適用** | 提案を承認し、稼働状態を更新 |
| **無視** | 保留（実態と異なる場合など） |

**毎朝、未処理の状態提案を先に確認することを推奨します。**

---

## 8. 配属取消フォロー

メニュー：**配属取消フォロー**

| 手順 | 説明 |
|------|------|
| 1 | 取消された配属、関係する社員・案件を確認 |
| 2 | 再提案や顧客連絡が必要か判断 |
| 3 | 対応完了後 **完了**をクリック |
| 4 | フォロー不要なら **却下** |

サイドバーの**赤い数字**は未完了タスク数です。

---

## 9. 事例：一通りの流れ

**状況**：A 社から Java 案件。1 名、来月 1 日開始。

| 手順 | 操作 | 画面 |
|------|------|------|
| 1 | メールを貼り付け、マッチング実行 | 案件マッチング |
| 2 | 案件登録、上位 3 名を候補追加 | 案件マッチング → 案件詳細 |
| 3 | 田中さんの履歴書を顧客へ送付、ステージ進行 | 案件詳細：田中 → 顧客提案済 |
| 4 | 顧客が面談を設定 | 面談設定済み → 選考中 |
| 5 | 田中さんの採用確定 | 採用確定、開始日＝来月 1 日 |
| 6 | 佐藤・鈴木が自動 LOST になったことを確認 | 案件詳細の候補一覧 |
| 7 | 翌日、状態提案を確認 | 状態提案：田中 → 稼働中、適用 |

---

## 10. よくある誤操作

| 誤操作 | 結果 | 正しい対応 |
|--------|------|------------|
| マッチングだけで派遣済みと思う | 社員状態は変わらない | 必ず採用確定まで実施 |
| 採用確定で開始日を空欄 | 有効な配属が作れない | 配属開始日は必須 |
| 状態提案を無視し続ける | 一覧の状態が実態とずれる | 毎日確認して適用 |
| 配属取消後にフォローを忘れる | 再提案の漏れ | フォロータスクを処理 |
