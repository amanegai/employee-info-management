## 1. 機能目的

営業が扱う**派遣案件**のライフサイクル全体を管理する。テキストマッチングによる候補者推薦、顧客選考の進行、採用確定と配属登録、案件状態の集計までを対象とする。加えて、社内要員が足りないときに他営業へ協力を求める **BP求援**、履歴書付きの **臨時候補**、アプリ内 **通知** を提供する。

> **人事（HR）は本機能ドメインにアクセス不可**（サイドバー非表示 + API 拒否）。

## 4. 業務フロー

### 4.1 案件マッチング

```
案件説明テキストを貼付 → POST /api/project-match
  → スキル解析 + 適合度ソート → 任意で「案件として登録」
```

### 4.2 選考進行（概要・既存社員候補）

```
案件詳細 → 候補を追加（マッチ結果または手動）
  → ステージ：MATCHED → PROPOSED → INTERVIEW_* → OFFERED
  → 採用確定（CONFIRMED）→ 配属を自動作成、他の並行選考をクローズ
  → 不採用/撤回/他案件確定 → 終了ステージ
```

### 4.3 案件状態

| 状態 | 意味 |
|------|------|
| OPEN | 募集中 |
| PARTIALLY_FILLED | 一部確定 |
| FILLED | 満員 |
| ON_HOLD | 保留 |
| CLOSED | 終了 |
| CANCELLED | キャンセル |

`OPEN` / `PARTIALLY_FILLED` / `FILLED` は確定人数と募集人数から**自動再計算**する（案件編集で人数変更時、採用確定時など）。`ON_HOLD` / `CLOSED` / `CANCELLED` は手動設定を優先し、人数変更では上書きしない。

完全な状態遷移・排他ルールは [project-workflow-design.md](../project-workflow-design.md) を参照。

### 4.4 BP求援

```
案件作成者または自社担当（または ADMIN）が求援を開始
  → 必要人数・伝言を入力 → 営業系ユーザーへ通知
  → 他営業が履歴書付き臨時候補を提出
  → 担当が確認 → 顧客提出 → 面談 → 採用確定 or 不合格終了
  → 満員時などは求援を自動終了可。終了後も再度求援可能
```

### 4.5 臨時候補（BP）ステータス

| 状態 | 意味 |
|------|------|
| PENDING | 担当確認待ち |
| APPROVED | 社内承認済 |
| REJECTED | 社内却下（履歴書ソフト削除） |
| SUBMITTED | 顧客提出済 |
| INTERVIEW_SCHEDULED | 面談調整中 |
| INTERVIEWING | 面談結果待ち |
| HIRED | 採用確定（BP社員登録＋配属＋履歴書を社員へ紐付け） |
| CLIENT_REJECTED | 顧客不採用（履歴書ソフト削除） |
| DECLINED | 辞退（履歴書ソフト削除） |
| WITHDRAWN | 提出者取下げ（履歴書ソフト削除） |

```
PENDING → APPROVED → SUBMITTED → INTERVIEW_SCHEDULED → INTERVIEWING → HIRED
                ↘ REJECTED
PENDING → WITHDRAWN
面談系 → CLIENT_REJECTED / DECLINED
```

**採用確定時の一括処理：** BP 種別の社員作成 → 履歴書を当該社員へ紐付け → `project_candidate` を CONFIRMED → 配属作成 → 案件の確定人数更新／ステータス再計算 → 必要に応じ求援自動終了。詳細（連絡先・スキル等）は採用後に社員画面で補完する。

**不合格時の履歴書：** ディスク上の実ファイルを即削除し、`file_attachment` は `deleted_at` 付きで残す（外キー・監査用）。ファイル管理一覧には出ない。

## 5. 画面詳細

### 5.1 案件マッチング

| 項目 | 説明 |
|------|------|
| 入力 | 案件の自由テキスト（スキル、単価、勤務地など） |
| 出力 | 適合度ソート一覧、マッチ理由 |
| 操作 | 社員詳細へ遷移、案件を作成して関連付け |

### 5.2 案件一覧

| 項目 | 説明 |
|------|------|
| 検索 | 顧客名、案件名、状態 |
| 集計 | 各状態の件数、候補数の要約 |
| 表示 | BP求援中バッジ（求援公開中の案件） |

### 5.3 案件詳細

| ブロック | 内容 |
|----------|------|
| 基本情報 | 取引先、単価、期間、必要スキル、募集人数・確定人数 |
| BP求援 | 開始/終了、必要スロット、伝言（作成者・担当・ADMIN のみ操作） |
| 臨時候補 | 提出フォーム、カード一覧（3列）、進捗バー、承認〜採用操作 |
| 候補一覧 | （既存社員）ステージ進捗バー、操作ボタン |
| 配属 | CONFIRMED 後の配属記録 |
| 操作 | ステージ変更、確定、却下、配属取消 |

採用フォーム表示中は当該臨時候補カードの操作ボタンを隠し、取消で再表示する。採用成功後は案件詳細（人数・ステータス・候補者）を静かに再取得する。

### 5.4 BP求援一覧

| 項目 | 説明 |
|------|------|
| 表示 | 求援中案件のカード一覧（必要人数、スキル、未確認臨時候補件数など） |
| 操作 | 案件詳細へ遷移 |

### 5.5 通知ベル

| 項目 | 説明 |
|------|------|
| 表示 | 未読件数バッジ、相対時刻、種別アイコン |
| 操作 | 個別既読＋リンク遷移、すべて既読、BP求援一覧へ |
| 更新 | 約 20 秒ポーリング |

## 7. 業務ルール

- **マッチ ≠ 採用**：マッチ結果は社員の稼働状態を変更しない
- **並行選考**：同一社員を複数案件の候補に同時登録できる
- **先着優先**：一方が CONFIRMED になると、他の進行中候補は自動で LOST
- **配属が状態を駆動**：CONFIRMED 配属のみが稼働状態に影響（[04-社員状態と配属フォロー](04-社員状態と配属フォロー.md) 参照）
- **候補ステージ**：`projectWorkflow.js` / `CandidateStage` 列挙で定義
- **BP求援操作**：案件の `created_by` または `owner_user_id`、もしくは ADMIN
- **臨時候補提出**：求援公開中かつ案件書込権限があれば提出可（求援開始者自身も含む）
- **臨時候補レビュー**：案件担当（owner）／作成者（owner 未設定時）／ADMIN
- **不合格履歴書**：REJECTED / CLIENT_REJECTED / DECLINED / WITHDRAWN で即ソフト削除（[07-ファイル管理](07-ファイル管理.md)）
- **採用履歴書**：HIRED 時は削除せず `employee_id` を付与
