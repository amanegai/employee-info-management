## 1. 機能目的

**取引先（顧客・委託元）**のマスタデータを維持する。会社情報、契約条件、担当者連絡先を管理し、案件・顧客活動・議事録・人事業務の送付など他モジュールの関連基盤とする。

---

## 2. 役割と権限

| 操作 | ADMIN | HR | DIVISION_HEAD | DEPT_HEAD | SALES_HEAD |
|------|:-----:|:--:|:-------------:|:---------:|:----------:|
| 一覧/詳細閲覧 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 新規/編集 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 削除 | ✓ | — | — | — | — |

取引先は「非案件ドメイン」の機能であり、**HR もアクセス可能**（案件ドメインと区別する）。

## 4. 業務フロー

```
一覧検索 → 詳細閲覧（担当者、関連案件/活動タブ）
  → 新規/編集 → マスタと連絡先を保存
  → 案件登録時に取引先名を選択または入力
```

## 5. 画面詳細

### 5.1 取引先一覧

| 項目 | 説明 |
|------|------|
| 検索 | 会社名、カナ、状態 |
| 操作 | 詳細、新規、編集 |

### 5.2 取引先詳細

| ブロック | 内容 |
|----------|------|
| 基本情報 | 社名、住所、業種、契約形態 |
| 担当者 | 連絡先一覧（氏名、部署、メール、電話） |
| 関連 | 案件・顧客活動への入口リンク（権限に応じて） |

### 5.3 取引先フォーム

| フィールド区分 | 例 |
|----------------|-----|
| 会社 | 正式名称、略称、法人番号 |
| 連絡 | 本社住所、代表電話 |
| 業務 | 支払サイト、契約区分、備考 |

## 6. API一覧

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/api/clients` | 一覧 |
| GET | `/api/clients/:id` | 詳細（担当者含む） |
| POST | `/api/clients` | 新規（担当者はリクエストボディで同時保存） |
| PUT | `/api/clients/:id` | 更新（担当者はリクエストボディで同時保存） |
| DELETE | `/api/clients/:id` | 削除（ADMIN） |

> 担当者（`clientContacts` / `internalContacts`）の独立 CRUD API（`/api/clients/:id/contacts`）は**存在しない**。`ClientService` が POST/PUT 時にボディ内の連絡先をまとめて永続化する。

---

## 7. 業務ルール

- 案件 `dispatch_project.client_name` は取引先マスタとの関連付け、またはテキスト併存が可能（実装に準拠）
- 取引先削除前に、関連する案件・活動の有無を確認する（外部キーまたは業務チェック）
- 人事業務の送付機能は取引先 ID により在籍社員一覧を取得する（[08-人事業務](08-人事業務.md)）
- 顧客活動・議事録との関連は [06-顧客活動と議事録](06-顧客活動と議事録.md) を参照
