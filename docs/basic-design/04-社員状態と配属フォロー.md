## 1. 機能目的

配属の確定/取消後に、社員の**稼働状態**（待機、稼働中、案件終了間近など）の提案または維持を行い、配属取消後のフォロー事項をタスク化して管理する。顧客対応や社内手続の漏れを防ぐ。

---

## 2. 役割と権限

| 操作 | ADMIN | DIVISION_HEAD | DEPT_HEAD | SALES_HEAD | HR |
|------|:-----:|:-------------:|:---------:|:----------:|:--:|
| 状態提案一覧の閲覧 | ✓ | ✓ | ✓ | ✓ | — |
| 提案の承認/却下 | ✓ | ✓ | ✓ | ✓ | — |
| 配属取消フォロー | ✓ | ✓ | ✓ | ✓ | — |

案件ドメインのサブ機能であり、HR はアクセス不可。

## 4. 業務フロー

### 4.1 状態自動提案（定時タスク）

```
日次で CONFIRMED 配属の start_date / end_date をスキャン
  → employee_status_suggestion を生成（例：終了間近 → 案件終了間近）
  → 営業が「状態提案」画面で確認後、employee.work_status に反映
```

### 4.2 配属取消フォロー

```
配属取消 API → assignment_cancel_followup タスクを作成
  → 一覧に未処理を表示
  → 担当が resolve（処理済）または dismiss（フォロー不要）を記録
```

### 5.1 社員状態提案

| 項目 | 説明 |
|------|------|
| 表示 | 社員名、現在状態、提案状態、理由、配属/案件の関連 |

| 項目 | 説明 |
|------|------|
| 表示 | 取消された配属、社員、案件、取消日、フォロー状態 |
| 操作 | 完了登録、却下（フォロー不要） |
| 備考 | 取消理由は配属取消 API に由来 |

## 6. API一覧

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/api/employee-status/suggestions` | 提案一覧 |
| POST | `/api/employee-status/suggestions/:id/apply` | 適用（承認） |
| POST | `/api/employee-status/suggestions/:id/dismiss` | 却下 |
| POST | `/api/employee-status/maintenance/run` | メンテナンス手動実行 |
| GET | `/api/assignment-cancel-followups` | フォロー一覧 |
| POST | `/api/assignment-cancel-followups/:id/resolve` | 完了 |
| POST | `/api/assignment-cancel-followups/:id/dismiss` | 却下 |

---

## 7. 業務ルール

- 提案は `EmployeeStatusMaintenanceService`（定時タスク）が生成する。人手確認が必要な状態変更は自動上書きしない
- `end_date` フィールド：主に退職予定 / 案件終了間近のシナリオで使用
- 配属取消はフォロー記録を作成し、営業と顧客のコミュニケーションをクローズできるようにする
- [03-案件と選考](03-案件と選考.md) における配属 CONFIRMED/CANCELLED と連動
