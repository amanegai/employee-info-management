## 1. 機能目的

派遣/SES 技術者の**基本情報、スキル、給与、評価、勤怠関連**などのマスタデータを一元管理し、部署に応じたデータ範囲の分離と一括インポートを支援する。

---

## 2. 役割と権限

| 操作 | ADMIN | HR | DIVISION_HEAD | DEPT_HEAD | SALES_HEAD |
|------|:-----:|:--:|:-------------:|:---------:|:----------:|
| 一覧/詳細閲覧 | ✓ | ✓ | 所管範囲 | 自部署 | 全社（人事部を除く） |
| 社員の新規/編集 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 所属部門・役職・役割の変更（**編集時**） | ✓ | ✓ | — | — | — |
| 社員削除 | ✓ | — | — | — | — |
| 給与 Tab 閲覧 | ✓ | ✓ | ✓ | ✓ | ✓（読取専用） |
| 給与編集 | ✓ | ✓ | ✓ | ✓ | — |
| CSV/JSON インポート | ✓ | ✓ | ✓ | ✓ | ✓ |
| マスタ一括登録（Excel） | ✓ | — | — | — | — |

権限関数：`canWrite()`、`canViewSalary()`、`canWriteSalary()`、`canChangeEmployeeDepartmentAndRole()`（`frontend/src/auth.js` / `SecurityService.java`）

- **所属部門・役職・役割**：新規登録時は `canWrite()` ロール全員が入力可。編集時は **ADMIN / HR のみ**変更可（`canChangeEmployeeDepartmentAndRole()`）。サーバー側 `EmployeeService.applyUpdateLocks()` で強制。
- **個人事業主 / BP**：編集時も所属部門は変更不可。役職・役割のみ ADMIN / HR が変更可。

## 4. 業務フロー

### 4.1 新規登録

```
一覧の「新規」→ フォーム入力 → POST /api/employees → 詳細へ遷移
```

### 4.2 編集

```
詳細の「編集」→ PUT /api/employees/:id
  → 営業ロール：給与フィールドはサーバー側で無視（applySalaryWritePermission）
```

### 4.3 一覧からの JSON/CSV インポート

```
一覧からインポート → JSON/CSV を解析 → POST /api/employees/import → マージまたは新規作成
```

### 4.4 マスタ一括登録（Excel・管理者専用）

画面：`/admin/master-import`（`MasterImportPage.jsx`）。**ADMIN のみ**。

```
テンプレート DL → Excel 記入 → 内容を確認（dryRun）→ 登録する
  → POST /api/admin/master/employees/import?dryRun=true|false
  → MasterImportService が複数シートを解析し createFromMaster
```

**社員テンプレート必須シート**（旧版・単一シートのみのファイルは不可）：

| シート | 内容 | 紐づけ |
|--------|------|--------|
| 社員 | 基本情報（1行＝1名） | — |
| 保有資格 | 資格（1行＝1件） | 社員ID |
| 関連技術 | カテゴリ・項目名・レベル（◎/〇/△） | 社員ID |
| 職務経歴 | 職歴（1行＝1案件） | 社員ID |
| 関連技術一覧 | 参照専用（取込対象外） | — |
| 記入説明 | 参照専用（取込対象外） | — |

**記入例（5行目）**：緑色・シート保護で編集・削除不可。取込時は「これは記入例」を含む行を自動スキップ。実データは **6行目以降**。

**子シート**：実データ行が無くてもシート自体は必須。社員ID は「社員」シートに存在すること。

**取込先**：「社員」→ 基本情報タブ、「保有資格／関連技術／職務経歴」→ スキル・資格・経歴タブ。

テンプレート再生成：`node scripts/generate-master-import-templates.mjs`

### 4.5 勤怠 Tab

```
対象月を選択 → GET /api/employees/:id/attendance?targetMonth=YYYY-MM
  → 勤務表/経費精算の関連ファイル状態を表示
```

## 7. 業務ルール

- **データ範囲**：`auth/DataScopeService` がロールに応じて閲覧可能な社員をフィルタ。`SALES_HEAD` はサーバー側で `resolveAllDepartmentsExceptHr()` により人事部を除外（全社閲覧だが人事部は対象外）
- **給与保護**：`SALES_HEAD` 保存時、サーバー側で給与変更を除去
- **所属部門・役職・役割（編集）**：`canChangeEmployeeDepartmentAndRole()` が false のロールは、更新 API 送信時もサーバーが既存値を保持（`applyUpdateLocks`）
- **稼働状態**：配属/定時タスクからの提案で更新。詳細は [04-社員状態と配属フォロー](04-社員状態と配属フォロー.md)
- **work_status 列挙**：待機中、稼働中、案件終了間近、退職予定 など
- **削除**：ADMIN のみ；関連データがある場合は業務チェックが必要
