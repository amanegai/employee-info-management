## 1. 功能目的

在配属确定/取消后，**建议或维护社員稼働状態**（待機、稼働中、案件終了間近等），并对配属取消后的跟进事项进行任务化管理，避免遗漏客户或内部手续。

## 4. 业务流程

### 4.1 状態自動提案（定时任务）

```
每日定时扫描 CONFIRMED 配属的 start_date / end_date
  → 生成 employee_status_suggestion（例：即将结束 → 案件終了間近）
  → 营业在「状態提案」画面确认后写入 employee.work_status
```

### 4.2 配属取消フォロー

```
配属取消 API → 创建 assignment_cancel_followup 任务
  → 一覧显示待处理项
  → 担当标记 resolve（已处理）或 dismiss（无需跟进）
```

---

## 7. 业务规则

- 提案由 `EmployeeStatusScheduler`（或同等定时任务）生成，不自动覆盖需人工确认的状态变更
- `end_date` 字段：主要用于 退職予定 / 案件終了間近 场景
- 配属取消触发跟进记录，便于营业与客户沟通闭环
- 与 [03-案件与选考](03-案件与选考.md) 中配属 CONFIRMED/CANCELLED 联动
