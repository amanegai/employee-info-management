## 1. 機能目的

社員に関連する**電子ファイル**（勤務表、証明書、契約、給与関連など）を一元管理し、社員・月・分類での検索を可能にする。勤怠・経費精算の取込フローとも連携する。

---

## 2. 役割と権限

| 操作 | ADMIN | HR | DIVISION_HEAD | DEPT_HEAD | SALES_HEAD |
|------|:-----:|:--:|:-------------:|:---------:|:----------:|
| 一覧/ダウンロード閲覧 | ✓ | ✓ | ✓ | ✓ | ✓ |
| アップロード/削除 | ✓ | ✓ | ✓ | ✓ | ✓ |

権限関数：`canViewFiles()`（全ログインユーザー）、`canWriteFiles()`（上表の書込可能ロール）

ファイル権限は案件ドメインと**独立**である。HR は案件にアクセスできなくとも、ファイル管理は可能。

## 4. 業務フロー

### 4.1 アップロード

```
ファイル選択 → 分類・対象社員・対象月（勤務表など）を指定
  → POST multipart → server の storage-dir に保存
  → メタデータを file_attachment に書き込み
```

### 4.2 勤怠/経費の同期

```
ファイル管理 → POST /api/files/batch（multipart）
  → syncAttendance / syncExpense フラグと更新 JSON を付与
  → 勤務表/経費の状態を同期
```

### 4.3 ダウンロード/削除

```
一覧 → ダウンロード GET /api/files/:id/download
  → 削除 DELETE（canWriteFiles）
```

削除は **ソフト削除**：`deleted_at` を立て、ディスク上の実ファイルも削除する。一覧検索は `deleted_at IS NULL` のみ。

### 4.4 BP臨時候補の履歴書（RESUME）

```
BP求援の臨時候補提出 → category=RESUME で file_attachment 登録（employee_id なし）
  → 採用確定（HIRED）→ employee_id を付与（社員へ紐付け）
  → 却下/不採用/辞退/取下げ → softDeleteForSystem（即ディスク削除）
```

業務からの削除はファイル管理権限を要求しない（`FileAttachmentService.softDeleteForSystem`）。詳細は [03-案件と選考](03-案件と選考.md) §4.5。

## 6. API一覧

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/api/files` | 一覧（絞り込み付き） |
| GET | `/api/files/meta/categories` | 分類マスタ |
| POST | `/api/files` | 単一アップロード（multipart） |
| POST | `/api/files/batch` | 一括アップロード（`syncAttendance` / `syncExpense` で勤怠・経費同期可） |
| GET | `/api/files/:id/download` | 内容のダウンロード |
| DELETE | `/api/files/:id` | 削除（ソフト削除） |

> メタデータ専用の `GET /api/files/:id`、および独立した `attendance-import` / `expense-import` エンドポイントは**存在しない**。勤怠・経費の取込はバッチ Upload のフラグで行う。

---

## 7. 業務ルール

- 物理ファイルの保存先：`app.storage-dir`（既定 `./storage`、Docker では volume マウント）
- ファイル名と MIME タイプは `file_attachment` に記録する
- `target_month` の形式は `YYYY-MM`（勤務表など月次ファイル向け）
- ユーザー削除およびシステム削除は、いずれも `deleted_at` 設定＋ディスク削除（行は監査・外キーのため残す）
- BP臨時候補が不合格終了した履歴書は即ソフト削除。DB 行の物理削除バッチは現状なし
- アップロードサイズ上限は `application.properties` の `spring.servlet.multipart` を参照
