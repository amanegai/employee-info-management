## 1. 機能目的

取引先に関する**営業活動**（訪問、会食、展示会など）および**議事録・課題**を記録し、顧客関係の維持と社内での情報共有を支援する。

> 会議室予約は機能 **MEETING_ROOM** として独立しており、本ドメインには含めない（[09-会議室予約](09-会議室予約.md) を参照）。

## 4. 業務フロー

### 4.1 顧客活動

```
活動一覧（日次/取引先で絞り込み）
  → 登録：日時、種別、取引先、参加者、内容
  → 編集/削除
```

### 4.2 議事録と課題

```
議事録一覧 → 会議記録を新規作成（日付、取引先、議題、決定事項）
  → 課題を関連付け（担当、期限、状態：未着手 / 対応中 / 完了 / 保留）
  → 課題を完了まで追跡
```

## 5. 画面詳細

### 5.1 顧客活動

| 項目 | 説明 |
|------|------|
| 活動種別 | 訪問、電話、会食、イベントなど（列挙は実装に準拠） |
| 関連 | 取引先、参加社員（任意） |
| 検索 | 期間、取引先、種別 |

### 5.2 議事録・課題

| 項目 | 説明 |
|------|------|
| 議事録 | 会議日、参加者、議題、内容、次回アクション |
| 課題 | タイトル、担当、期限、優先度、状態（未着手 / 対応中 / 完了 / 保留） |
| 関係 | 課題は議事録配下、または単独管理が可能 |

## 6. API一覧

### 顧客活動

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/api/client-events` | 一覧 |
| GET | `/api/client-events/:id` | 詳細（ID 指定） |
| POST | `/api/client-events` | 新規作成 |
| PUT | `/api/client-events/:id` | 更新 |
| DELETE | `/api/client-events/:id` | 削除 |

### 議事録・課題

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/api/client-meetings` | 議事録一覧 |
| GET | `/api/client-meetings/:id` | 議事録詳細 |
| POST | `/api/client-meetings` | 議事録新規 |
| PUT | `/api/client-meetings/:id` | 議事録更新 |
| DELETE | `/api/client-meetings/:id` | 議事録削除 |
| GET | `/api/client-issues` | 課題一覧 |
| GET | `/api/client-issues/:id` | 課題詳細 |
| POST | `/api/client-issues` | 課題新規 |
| PUT | `/api/client-issues/:id` | 課題更新 |
| DELETE | `/api/client-issues/:id` | 課題削除 |

課題状態の列挙：`未着手` / `対応中` / `完了` / `保留`（`ClientIssueData.STATUSES`。英語 OPEN/DONE ではない）

---

## 7. 業務ルール

- 活動・議事録はいずれも有効な取引先に関連付ける（取引先マスタは [05-取引先管理](05-取引先管理.md)）
- 課題の状態変更時は更新者と時刻（`updated_at`）を記録できる
- 議事録削除時は配下課題を適切に処理する（カスケード、または削除禁止）
