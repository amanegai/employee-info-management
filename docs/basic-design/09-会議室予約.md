## 1. 機能目的

社内会議室の空き状況を**月曜始まりの週次カレンダー**で可視化し、ログインユーザーが空き枠を選んで即座に予約・変更・取消できるようにする。  
会議室マスタ（名称・フロア・定員・設備・時間枠・利用時間帯）の登録・変更・削除は **ADMIN のみ**。承認フローはなく、新規予約は即 `CONFIRMED`、取消は `CANCELLED`（論理取消）とする。

## 4. 業務フロー

### 4.1 会議室マスタ作成（ADMIN）

```
「新規会議室」→ 入力（名必須、フロアは数字のみ）
  → POST /api/meeting-rooms（active=true、既定 slot=30分・09:00〜22:00）
  → 作成した室をカレンダーで選択
```

### 4.2 予約作成

```
会議室選択 → 週グリッドの空きセルをクリック
  → 件名・日付・開始・所要枠・備考を入力
  → POST /api/meeting-room-reservations（status=CONFIRMED）
```

### 4.3 予約編集・取消

```
予約ブロックをクリック
  → 本人/ADMIN: 編集モード / 他人: 閲覧モード
  → PUT で更新（日付は FE でロック、会議室変更不可）
  → DELETE で取消（status=CANCELLED、レコードは残す）
```

### 4.4 週カレンダー

```
月曜始まり。前週 / 今週 / 翌週
  → dateFrom〜dateTo + roomId で CONFIRMED 予約を取得
  → 自分/他人で色分け。土日・祝は表示強調のみ（予約は可能）
```

### 4.5 会議室削除（ADMIN）

```
設定モーダルで削除（または利用不可保存フロー）
  → DELETE /api/meeting-rooms/{id}
  → 関連予約を先に物理削除してから室を削除
```

> UI の「利用可能 OFF」保存は削除確認につながる実装。BE の `active=false` への PUT（論理無効化）も可能だが、現行 UI の主経路は物理削除。

## 6. API 一覧

`SecurityConfig` は `/api/**` → authenticated。会議室専用 matcher はなく、Service で認可。

### 6.1 会議室 `/api/meeting-rooms`

| 方法 | パス | 説明 | 権限 |
|------|------|------|------|
| GET | `/api/meeting-rooms` | active 一覧 | canView |
| GET | `/api/meeting-rooms?all=true` | 全件 | canManage |
| GET | `/api/meeting-rooms/{id}` | 1 件 | canView |
| POST | `/api/meeting-rooms` | 作成 | canManage |
| PUT | `/api/meeting-rooms/{id}` | 更新 | canManage |
| DELETE | `/api/meeting-rooms/{id}` | 室＋関連予約の物理削除 | canManage |

### 6.2 予約 `/api/meeting-room-reservations`

| 方法 | パス | 説明 | 権限 |
|------|------|------|------|
| GET | `?dateFrom&dateTo&roomId?` | 期間検索（CONFIRMED） | canView |
| GET | `/{id}` | 1 件（CANCELLED も可） | canView |
| POST | `/` | 作成 | canWrite |
| PUT | `/{id}` | 更新 | canWrite + canModify |
| DELETE | `/{id}` | 取消（CANCELLED） | canWrite + canModify |

**リクエスト要点**

- 会議室: `{ name, floor, capacity, equipment, slotMinutes, businessStart, businessEnd, active, sortOrder }`
- 予約: `{ roomId, title, startAt, endAt, description }`（日時は `yyyy-MM-dd'T'HH:mm[:ss]`）

## 7. 業務ルール

- **重複禁止**: 同一室・`CONFIRMED` 同士で時間帯が重なる場合は 409
- **所有権**: 編集・取消は予約者本人または ADMIN
- **時間枠**: `slot_minutes` ∈ {15, 30, 60}。開始・終了・所要は枠に整合
- **利用時間帯**: `[businessStart, businessEnd]` 内。同一日内のみ（日跨ぎ不可）
- **室変更不可**: 更新時に `roomId` を変えられない
- **無効室**: `active=false` への新規予約不可。通常一覧は active のみ
- **名称一意**: フロア（null は空文字）＋名称の正規化（前後空白・大小無視）で UNIQUE
- **取消**: 論理 `CANCELLED`。検索結果から除外
- **室削除**: 関連予約を先に物理 DELETE
- **DTO**: `ownedByCurrentUser` で FE が自分判定
